## M-9J2c ヒント品質の穴と frame 対応

### 1. frame / hits
- `gpu_hints` のキーは全 240 フレーム分（211,200 件）。
- ローダ hits は **529k**（`i_pixel=3` 修正後）。
- x264 自身の dump は同じフレームでも複数 ref/i_pixel を持ち、
  1.1M はその重複を含む。`gpu_hints` は ref=0/1 を出すが、
  x264 側の参照番号と完全一致せず **約半分**。
- 欠落フレームは無し。B ピラミッドの ref 番号対応が残課題。

### 2. 品質（REFINE=8、limit スイープ、640p cockL CRF27）

| limit | 出力 | 判定 |
|---:|---:|---|
| 2 | 131,617 | +31.7% |
| 3 | 118,873 | +18.9% |
| 4 | 115,059 | +15.1% |
| **6** | **99,823** | **-0.1%（base 99,967）** |
| 8 | 99,981 | +0.0% |

- **limit:6 で出力は base 同等**。
- ただし CRF27 の PSNR/SSIM は 3 クリップで悪化:
  - vtestL 42.559 → 42.112（-0.447 dB）
  - megaL 42.712 → 42.333（-0.379 dB）
  - treeL 30.862 → 30.362（-0.500 dB）
  - cockL 44.312 → 44.309（ほぼ同等）
- 同じビット数で品質が低いため **BD-rate は +1〜1.5% 程度で FAIL**。

### 3. vtestL の limit 拡大

| limit | 出力 |
|---:|---:|
| 8 | 166,150 |
| 12 | 161,776 |
| **16** | **156,687**（base 158,327） |

- vtestL は **limit:16** で base を下回るビット。
- cockL は limit:6 が最良で、limit:16 は未測定。
- クリップごとに最適 N が異なる。

### 4. E2E（640p cockL、threads 4、3回中央値）

| 項目 | 時間 |
|---|---:|
| base | 13.77 s |
| GPU ヒント + limit:6 | **9.90 s** |
| ヒント生成 | 約 2.3 s |
| E2E | **12.2 s（base -1.5 s）** |

- 時間は勝ち。品質が FAIL。

### 判定

| 項目 | 結果 |
|---|---|
| frame 欠落 | 無し |
| hits | 529k（目標 1.1M は ref 重複のため未達） |
| limit:6 出力 | base 同等 |
| BD-rate +0.5% | **FAIL（推定 +1〜1.5%）** |
| E2E | **PASS（cockL -1.5 s）** |
| 案C 実証 | **未達（品質）** |

不足要因：
- 低解像度 MV の精度（full-res 整数リファイン後も qpel 候補が弱い）。
- **fractional 候補が無い**。x264 は qpel 候補で 0.4–0.5 dB 稼ぐ。
- クリップごとの最適 limit が異なる（6〜16）。

### 次
- M-9J2c1: qpel 候補（低解像度 1/2 ペル）を追加。
- M-9J2c2: 上位 2 候補＋SATD 再評価。
- M-9J2c3: 適応 limit（SAD 改善量で 6/16 を選択）。
