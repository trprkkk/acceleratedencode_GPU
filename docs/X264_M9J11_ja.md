## M-9J11 1080p 2MB 超ホスト領域の解体（タイムボックス終了）

### 試したこと
1. `src`/`ref` を静的 BSS（2.3 MB）に変更。
2. `me_batch` の帯を 4 MB 行 → 1 MB 行に変更。
3. 1 MB チャンクの `cuMemcpyHtoD`。
4. `cuMemAllocHost` の pinned staging + `memcpy`。

### 結果
- 1280x720: 成功。
- 1920x1080 n=1: フレーム0のみ成功。
- 1920x1080 n=2: **SIGSEGV**（フレーム1）。
- クラッシュ位置: `cuda_me_batch` 内の
  `memcpy(pin, ref - AEG_PAD*stride - AEG_PAD, 253952)`。
  - `src` / `ref` は BSS 内で有効（`big_src+63520`、`big_ref+63520`）。
  - `dest`（pinned）は `cbytes` 確保済み。
  - それでも `memcpy` が落ちる。
- 2 MB 超のホスト領域を静的にしても再現するため、
  **連続領域のサイズだけが原因ではない**。
- 1080p は **凍結**。

### 1080p の生成コスト（CPU フォールバック）
- 120f: **8.0 s（66.7 ms/frame）**。
- GPU が通れば 10 ms/frame 前後が期待できるが、未達。

### 640p
- slow / limit:4 の BD-rate は PASS（平均 -0.12%）。
- E2E は **3/4**（treeL +0.51 s）。
- treeL スキップ判定は未実装。

### 判定
| 項目 | 結果 |
|---|---|
| 1080p が動くか | **フレーム0のみ** |
| 採用した修正 | BSS 静的確保（クラッシュは残存） |
| 原因 | `memcpy` の pinned 宛先で落ちる。2MB 説は否定 |
| 1080p E2E | **未測定** |
| 1080p 生成（CPU） | 66.7 ms/frame |
| 640p 4/4 | **未達（3/4）** |
| 640p BD-rate | PASS |

### 凍結判断
1080p はこれ以上追わず、**640p slow の 4/4 と treeL スキップ**を優先する。
1080p は「CPU フォールバック 66.7 ms/frame」を将来の見積り値として記録。
